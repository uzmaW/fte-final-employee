## Vault Directory Structure
- `/Needs_Action/` - Inbox of tasks from Watchers
- `/In_Progress/<agent>/` - Tasks currently being worked on (claim by moving here)
- `/Plans/` - Generated plans with checklists (prefixed PLAN_*)

- `/Pending_Approval/` - Actions requiring human approval (prefixed with action type)
- `/Approved/` - User-approved files ready for execution
- `/Rejected/` - User-rejected actions (log and skip)
- `/Logs/` - Audit trail in YYYY-MM-DD.json format

- `/Company_Handbook.md` - Rules of engagement and thresholds
- `/Business_Goals.md` - Quarterly objectives and metrics
- `/Accounting/Current_Month.md` - Transaction ledger
## Reading from Vault
When processing Needs_Action items:
1. **List all files**: Use Glob to scan `/Needs_Action/*.md`
2. **Parse metadata**: Extract YAML frontmatter (type, priority, source, created timestamp)

4. **Deduplicate**: Check `/In_Progress/` to avoid duplicate processing
5. **Report**: List what you found with counts by type

--# Ralph Wiggum Loop Skill
The "Ralph Wiggum Stop Hook" is a pattern that keeps Claude iterating until a task is complete.
Rather than exiting after one attempt, it loops until the task file moves to `/Done/`.
## How It Works
1. **Task Created**: Orchestrator.py writes state file to `/Tasks/TASK_<id>.md`
2. **Claude Works**: You read task, execute steps, write progress to vault
3. **Check Completion**: At end, check if task file moved to `/Done/`
4. **Loop or Exit**:
- If in `/Done/`: Task complete, exit
- If still in `/In_Progress/`: Check max iterations, continue if < 10
- If stuck: Log error and abort
## Task State File Format
```yaml
--type: task
task_id: process_weekly_inbox
created: 2026-01-28T08:00:00Z
status: in_progress
max_iterations: 10
current_iteration: 1
--## Objective
Process all items in /Needs_Action/ and move completed items to /Done/
## Steps
- [ ] List all files in /Needs_Action/
- [ ] Process each file by type
- [ ] Create plans/approvals as needed
- [ ] Move processed files to /Done/
- [ ] Update Dashboard.md
- [ ] COMPLETION: All /Needs_Action items processed

Iteration Pattern
Iteration 1:
●​ List files in /Needs_Action/
●​ Find 5 items to process
●​ Start processing first item
Iteration 2:
●​ Check progress file
●​ Continue with next items
●​ Create approval files
Iteration 3:
●​ All items processed
●​ Move task to /Done/TASK_process_weekly_inbox_2026-01-28.md
●​ Exit (completion detected)

Loop Detection
Prevent infinite loops:
Copy

# In orchestrator
MAX_ITERATIONS = 10
if current_iteration > MAX_ITERATIONS:
move_to_done(task_id, "MAX_ITERATIONS_EXCEEDED")
exit_with_error()

Completion Strategies
Strategy 1: File Movement (Recommended)

Task is complete when file moves to /Done/:

fi

import time
import logging
from pathlib import Path
from abc import ABC, abstractmethod
import json
from datetime import datetime
class BaseWatcher(ABC):
"""
Base class for all Watchers. A Watcher is a lightweight daemon that monitors
external sources (Gmail, WhatsApp, bank accounts) and writes .md files to
/Needs_Action/ for Claude to process.
These files trigger Claude Code with the appropriate skills:
- EMAIL_* files → gmail-processor skill
- WHATSAPP_* files → whatsapp-handler skill
- TRANSACTION_* files → financial-auditor skill
"""
def __init__(self, vault_path: str, check_interval: int = 60):
self.vault_path = Path(vault_path)

self.needs_action = self.vault_path / 'Needs_Action'
self.check_interval = check_interval
self.logger = logging.getLogger(self.__class__.__name__)
self.processed_items = set() # Track what we've already reported
# Ensure directories exist
self.needs_action.mkdir(parents=True, exist_ok=True)
@abstractmethod
def check_for_updates(self) -> list:
"""Return list of new items to process from external source"""
pass
@abstractmethod
def create_action_file(self, item) -> Path:
"""Create .md file in Needs_Action folder"""
pass
def run(self):
"""Main loop - run continuously"""
self.logger.info(f'Starting {self.__class__.__name__}')
while True:
try:
items = self.check_for_updates()
for item in items:
self.create_action_file(item)
self.logger.info(f'Created action file for: {item}')
except Exception as e:
self.logger.error(f'Error in check loop: {e}', exc_info=True)
time.sleep(self.check_interval)
def _create_markdown_file(self, filename: str, frontmatter: dict, content: str) -> Path:
"""Helper to create properly formatted .md file with YAML frontmatter"""
# Build YAML frontmatter
yaml_lines = ['---']
for key, value in frontmatter.items():
if isinstance(value, str):
yaml_lines.append(f'{key}: {value}')
else:
yaml_lines.append(f'{key}: {json.dumps(value)}')
yaml_lines.append('---')
yaml_section = '\n'.join(yaml_lines)
# Combine with content
full_content = f'{yaml_section}\n\n{content}'

filepath = self.needs_action / filename
filepath.write_text(full_content)
return filepath

from base_watcher import BaseWatcher
from playwright.sync_api import sync_playwright
from pathlib import Path
from datetime import datetime
import os
class WhatsAppWatcher(BaseWatcher):
"""
Monitors WhatsApp Web for urgent messages (keywords: invoice, payment, urgent, etc).
Uses Playwright for browser automation.
Creates WHATSAPP_* files that trigger whatsapp-handler skill.
"""
def __init__(self, vault_path: str, session_path: str, check_interval: int = 30):
super().__init__(vault_path, check_interval)
self.session_path = Path(session_path)
self.keywords = ['invoice', 'payment', 'urgent', 'asap', 'help', 'order', 'quote']
self.last_seen_ids = set()
def check_for_updates(self) -> list:
"""Check for unread WhatsApp messages containing keywords"""
messages = []
try:
with sync_playwright() as p:
browser = p.chromium.launch_persistent_context(
str(self.session_path),
headless=True
)
if not browser.pages:
self.logger.warning("No pages in persistent context")
return messages
page = browser.pages[0]

page.goto('https://web.whatsapp.com', timeout=30000)
try:
page.wait_for_selector('[data-testid="chat-list"]', timeout=10000)
except:
self.logger.warning("Could not find chat list")
browser.close()
return messages
# Find unread chats
unread_chats = page.query_selector_all('[aria-label*="unread"]')
for chat in unread_chats:
try:
text = chat.inner_text().lower()
if any(kw in text for kw in self.keywords):
# Extract sender and message preview
sender_elem = chat.query_selector('[data-testid="cell-frame-title"]')
sender = sender_elem.inner_text() if sender_elem else "Unknown"
msg_id = f"{sender}_{datetime.now().timestamp()}"
if msg_id not in self.last_seen_ids:
messages.append({
'sender': sender,
'preview': text[:200],
'id': msg_id,
'timestamp': datetime.now().isoformat()
})
self.last_seen_ids.add(msg_id)
except Exception as e:
self.logger.warning(f"Error processing chat: {e}")
browser.close()
except Exception as e:
self.logger.error(f"Error in WhatsApp watcher: {e}", exc_info=True)
return messages

Understanding Agent Skills Architecture

What are Agent Skills?
Agent Skills are modular packages of instructions, templates, and reference materials
that teach Claude how to complete specific tasks repeatably. Instead of embedding all
instructions in a conversation, skills live in dedicated files that Claude loads dynamically.
Traditional Approach (Monolithic):
Claude reads one large prompt
→ Follows instructions
→ Completes task
→ No reuse, no discovery

Skills Approach (Modular):
Claude discovers available skills
→ Loads relevant skill (SKILL.md)
→ Reads templates, examples, references as needed
→ Completes task
→ Skill reusable across contexts

--## Watcher System Design
### Overview: The Sensory System
Watchers are lightweight Python daemon processes that continuously monitor external sources
(Gmail, WhatsApp, bank APIs) and create action files for Claude to process. They solve the
fundamental problem: **Claude can't listen to the internet 24/7**, but watchers can.

### Base Watcher Architecture
**File: `watchers/base_watcher.py`**
All Watchers inherit from `BaseWatcher`, which provides standard patterns for:
- Polling external sources
- Creating markdown files with proper formatting
- Deduplication (don't process same item twice)
- Error handling and logging
```python
import time
import logging
from pathlib import Path
from abc import ABC, abstractmethod
import json
from datetime import datetime
class BaseWatcher(ABC):
"""
Base class for all Watchers. A Watcher is a lightweight daemon that monitors
external sources (Gmail, WhatsApp, bank accounts) and writes .md files to
/Needs_Action/ for Claude to process.
These files trigger Claude Code with the appropriate skills:
- EMAIL_* files → gmail-processor skill
- WHATSAPP_* files → whatsapp-handler skill
- TRANSACTION_* files → financial-auditor skill
- FILE_* files → vault-operations skill
"""
def __init__(self, vault_path: str, check_interval: int = 60):
"""
Initialize a Watcher.
Args:
vault_path: Path to Obsidian vault root
check_interval: Seconds between polling external source (default 60)
"""
self.vault_path = Path(vault_path)
self.needs_action = self.vault_path / 'Needs_Action'
self.check_interval = check_interval
self.logger = logging.getLogger(self.__class__.__name__)
self.processed_items = set() # Track what we've already reported

# Ensure directories exist
self.needs_action.mkdir(parents=True, exist_ok=True)
@abstractmethod
def check_for_updates(self) -> list:
"""
Check external source for new items.
Returns:
List of new items from source (subclass-specific format)
"""
pass
@abstractmethod
def create_action_file(self, item) -> Path:
"""
Create .md file in Needs_Action folder for Claude to process.
Args:
item: Item from check_for_updates()
Returns:
Path to created markdown file
"""
pass
def run(self):
"""
Main loop - run continuously in background.
Polls check_for_updates() every check_interval seconds.
"""
self.logger.info(f'Starting {self.__class__.__name__}')
while True:
try:
items = self.check_for_updates()
for item in items:
self.create_action_file(item)
self.logger.info(f'Created action file for: {item}')
except Exception as e:
self.logger.error(f'Error in check loop: {e}', exc_info=True)
time.sleep(self.check_interval)
def _create_markdown_file(self, filename: str, frontmatter: dict, content: str) -> Path:
"""
Helper to create properly formatted .md file with YAML frontmatter.

Args:
filename: Name of file (e.g., 'EMAIL_123.md')
frontmatter: Dict of YAML fields
content: Markdown content
Returns:
Path to created file
"""
# Build YAML frontmatter
yaml_lines = ['---']
for key, value in frontmatter.items():
if isinstance(value, str):
yaml_lines.append(f'{key}: {value}')
else:
yaml_lines.append(f'{key}: {json.dumps(value)}')
yaml_lines.append('---')
yaml_section = '\n'.join(yaml_lines)
# Combine with content
full_content = f'{yaml_section}\n\n{content}'
filepath = self.needs_action / filename
filepath.write_text(full_content)
return filepath

def log_action(self, action_type, details, status, actor='claude'):
log_file = self.logs / f"{datetime.now().strftime('%Y-%m-%d')}.json"
entry = {
'timestamp': datetime.now().isoformat(),
'action_type': action_type,
'actor': actor,
'details': details,
'status': status
}
# Append to daily log file
entries = []
if log_file.exists():
entries = json.loads(log_file.read_text())
entries.append(entry)
log_file.write_text(json.dumps(entries, indent=2))
# Retention: Keep 90 days
self.cleanup_old_logs()
def cleanup_old_logs(self):
cutoff = datetime.now() - timedelta(days=90)
for log_file in self.logs.glob('*.json'):
if log_file.stat().st_mtime < cutoff.timestamp():
log_file.unlink()

Retry Logic
Copy

from functools import wraps
import time
def with_retry(max_attempts=3, base_delay=1, max_delay=60):
def decorator(func):
@wraps(func)
def wrapper(*args, **kwargs):
for attempt in range(max_attempts):
try:
return func(*args, **kwargs)
except TransientError as e:
if attempt == max_attempts - 1:
raise
delay = min(base_delay * (2 ** attempt), max_delay)
logger.warning(f'Attempt {attempt+1} failed, retrying in {delay}s')
time.sleep(delay)
return wrapper
return decorator
